## 二、本次修复的违规实现（commit `1825d22`）

1. **弱确认列表查询未显式传 `page_size`**（§C.3-1）：默认仅返回 ~100 条，同名文件排在 100 名之外时弱确认会误判"未找到"。已修复：`listFiles` 显式携带 `page_size=1000`，单测断言请求含该参数。
2. **列表可能截断时盲目自动重传**（§C.3-5）：原实现在"未找到候选"时一律 RETRY 重传——若列表实际被截断（目录超 1000 文件），这是文档明令禁止的行为。已修复：
   - 新增 `ListResult.possiblyTruncated`（结果数 ≥ 请求上限即视为不可证完整）；
   - 新增 `WeakConfirm.decide()` 决策函数（真值表单测锁定）：同名+size 相符→弱确认结案；同名异物→-2/-3 换名（≤3）；无候选+列表完整→同 upload_id 安全重传；**无候选+列表可能截断→新增 UNRESOLVED「待人工确认」状态：保留任务/原件/凭据，不自动重传**，UI 提供人工重试入口。
3. **目录补救回退的 404 识别**（§B.4 定点确认项）：原实现仅识别 HTTP 404。已改为同时识别 HTTP 404 与 HTTP 200+业务码 404 两种形态，且仅在 CREATE 阶段触发建目录（配对时服务端已自动建「移动端取证」，此路径仅覆盖用户事后删目录的边缘情况）。业务 404 回退有专门单测。
