## A. 设备授权

### A.1 配对码兑换

**端点**：`POST /api/v4/sodayo/device/token`（无认证要求，配对码即凭证）[SOURCE_CHECKED: router.go:355]

**请求**：
```json
{"pair_code":"AB12CD34EF","device_name":"p60-sprint"}
```
- `pair_code`：10 位，必填 [SOURCE_CHECKED: sodayo_device.go:157 binding:"required,len=10"]
- `device_name`：必填 max=64，须与网页配对时填写一致（防冒领）[SOURCE_CHECKED: sodayo_device.go:158]

**成功响应**（API_CHECKED，隔离实测）：
```json
{"code":0,"data":{"device_id":2,"device_token":"sdkt_dcHMxxxx","expires_in":7776000,"ingest_uri":"cloudreve://my/移动端取证","scope":"ingest"},"msg":""}
```
- `device_token`：`sdkt_` 前缀，明文仅此一次返回 [SOURCE_CHECKED: DeviceAuth.kt:105-106 已正确提取]
- `expires_in`：秒（7776000 = 90 天）
- `ingest_uri`：授权目录（Android 上传的目标路径）

**失败码**（API_CHECKED）：

| JSON code | 含义 | 说明 |
|---|---|---|
| **404** | `pair code invalid or expired / already used` | 码无效/过期/已被兑（**不是上传冲突码 40004**）[SOURCE_CHECKED: serializer.CodeNotFound=404, error.go:81] |
| 403 | `device name mismatch` / `cloud drive access not granted` | 名不符 / 员工非 active / 无 clouddrive.basic |
| 403 | 配对码生成阶段即拒 | 无 clouddrive.basic 的员工无法生成配对码 |

**并发语义**：同一配对码并发兑换恰一成功（单事务 CAS）[API_CHECKED: 隔离 5 并发=1 成功 4×404]

### A.2 sdkt_ Token 权限范围

| 能力 | 允许 | 依据 |
|---|---|---|
| 上传到 `cloudreve://my/移动端取证/` | ✅ | middleware 白名单 [SOURCE_CHECKED: sodayo_device.go:357-389] |
| 列表 `GET /file?uri=cloudreve://my/移动端取证` | ✅ | 同上 |
| 建目录（白名单内） | ✅ | 同上 |
| 访问根目录 `cloudreve://my` | ❌ 403 | 白名单外 |
| 访问子目录（取证目录内子路径） | ✅ | `[/子路径]` 允许 |
| 浏览他人空间 | ❌ 403 | URI 白名单+owner 约束 |
| OA 证据关联（bind） | ❌ 401 | 仅网页 JWT |
| 设备管理（list/revoke） | ❌ 401 | 仅网页 JWT |

### A.3 Token 失效语义

| 触发 | HTTP 层 | JSON code | 恢复方式 |
|---|---|---|---|
| 设备撤销 | **401** | 40020 | 仅用户重新配对（不可逆） |
| 员工冻结 | **401** | 40020 | **解冻后同 Token 自动恢复**（无需重新配对）[SOURCE_CHECKED: AuthorizeDeviceToken 逐请求实时查 user.Status] |
| OA 权限回收 | **401** | 40020 | 权限恢复后同 Token 恢复（≤5 分钟缓存延迟） |
| Token 过期（90 天） | **401** | 40020 | 重新配对 |
| URI 越界 | **403** | 403 `limited to ingest folder` | **不触发 AUTH_SUSPECT**——修客户端 bug |
| 会话绑定不符 | **403** | 403 `not bound to this device` | 不触发 AUTH_SUSPECT |

**关键规则**：40020 对应的撤销、冻结、权限回收、Token 到期等原因**不能仅由这一业务码可靠区分**。APK 收到 40020 应标记 AUTH_SUSPECT（暂停+保留 Token+保留本地视频），**不立即清除 Token**。仅用户明确操作「重新配对」时覆盖。[SOURCE_CHECKED: AuthorizationDeviceToken L215-245]

**⚠️ HTTP 层存在不同错误包装形态**（隔离环境观察及源码核对，**非生产实测**）：
- 部分网页 JWT 端点的业务失败以 HTTP 200 + 非零 JSON `code` 表达。
- 设备 Token 请求在中间件鉴权失败时可返回真实 HTTP 401/403 + JSON `code`。
- 客户端不得假定任一类端点**永远**固定 HTTP 状态；应先安全解析响应体，再综合 HTTP 状态与业务 `code` 判定。

## B. 文件上传

### B.1 创建会话

**端点**：`PUT /api/v4/file/upload`（Bearer sdkt_）

**请求**：
```json
{"uri":"cloudreve://my/移动端取证/rec-20261021.mp4","size":188332892,"last_modified":1791800000000,"mime_type":"video/mp4"}
```

| 字段 | 必填 | 类型/单位 | 说明 |
|---|---|---|---|
| `uri` | 是 | string | **原始 UTF-8 中文**（不 percent-encode）[API_CHECKED: percent 形态被 403 拒] |
| `size` | 是 | int64 字节 | 精确字节数 |
| `last_modified` | 否 | int64 **Unix 毫秒** | [SOURCE_CHECKED: upload.go:84 `time.UnixMilli`] |
| `mime_type` | 否 | string | |
| `policy_id` | **否** | string | 缺省=默认存储策略 [API_CHECKED: 有/无均 code=0] |

**成功响应**（API_CHECKED）：
```json
{"code":0,"data":{"session_id":"2c2a8028-xxxx","upload_id":"","chunk_size":26214400,"expires":1792599970,"storage_policy":{"id":"0dcN","name":"Default storage policy","type":"local","max_size":0}},"msg":""}
```
- `chunk_size`：字节（实测 26214400 = 25 MB）——分片大小以此为准
- `expires`：**Unix 秒时间戳**（非相对秒数）[SOURCE_CHECKED: response.go:154]

### B.2 分片上传

**端点**：`POST /api/v4/file/upload/{session_id}/{index}`（Bearer sdkt_）

- `index` 从 0 递增
- 最后一片 = 余数（例：188332892 / 26214400 = 7 完整片 + 末片 **4,832,092** 字节）
- `Content-Type: application/octet-stream`
- **实际字节数必须与该分片位置精确一致**（否则 40013）
- 分片累计达 `size` 自动合并完成（无显式完成端点）
- **完成后重发分片 = 40011**（会话已关闭）
- **会话-设备绑定**：仅本设备创建的会话可用（跨设备 = 403 `not bound`）

### B.3 会话/分片状态查询

**结论：不存在设备 Token 可用的会话详情或已传分片查询端点。** [SOURCE_CHECKED: 路由仅有 PUT（创建）+ POST（分片），无 GET session]

**APK 建议**：进程重启后无法从服务端查询已传分片；本地应持久化 `session_id`、上传进度和确认回执，但**本地记录不能证明服务端仍持有相同会话状态**。重启后须按契约执行保守恢复：仅在可确认会话有效且分片状态一致时继续，否则使用同一确定性上传标识重新建立上传尝试并执行冲突弱确认。不要无条件认定重发相同 index 或重用旧 session 一定成功；所有不确定状态保留本地原件。

### B.4 上传失败自动回退

APK 已实现的 `createSessionWithFallback`（目标目录不存在时创建目录再重试）据开发方代码自审与服务端流程相容 [APK_SOURCE_REPORTED: CloudreveV4Uploader.kt:117-144]。实现中应确认这里识别的是实际 JSON 业务 `code=404`、HTTP 404，还是两者组合，避免对所有 404 一律建目录。

## C. 文件冲突与弱确认

### C.1 40004 触发条件

**按完整 URI 精确匹配**——同一目录下同文件名才返回 40004。不同目录同名文件不冲突。[API_CHECKED]

例：`cloudreve://my/移动端取证/rec.mp4` 已存在，再次 PUT 同 URI → 40004 `Object existed`。但 `cloudreve://my/其他目录/rec.mp4` 不受影响。

**服务端行为**：同名冲突时**不覆盖原件**（size 不同的旧文件保持不变）。[API_CHECKED: 隔离实测]

### C.2 40011 触发条件

会话无效——两种不可区分的语义：
1. 会话已完成（文件已合并）
2. 会话已过期/异常

### C.3 弱确认流程（APK 必须）

1. 收到 40004/40011 后，向目标取证目录发起 `GET /api/v4/file?uri=<URL-encoded ingest_uri>&page_size=1000`；注意这里的 `uri` 是 **URL 查询参数，应 percent-encode**，与创建会话 JSON 中的原始 UTF-8 URI 不同。
2. 仅在**本次任务目标目录**中按精确文件名查找候选，不跨目录匹配。
3. 找到同名且 `size` 与本地一致 → 只做 `name+size` **弱确认**（非内容哈希校验），按既定契约结案并保留原件。
4. 找到同名但大小不一致 → 按 APK 既有同名异物策略处理（有界后缀 `-2/-3`），不能覆盖旧文件。
5. 未找到候选时**先判断列表是否可能截断**。若列表恰达到请求上限、返回范围不明或无法证明结果完整，应标记「确认不充分」，保留任务和原件，**不可仅因未找到就断言服务端没有该文件并自动重传**；可证明不存在时才按 v2.2 的确定性 upload_id 安全重试策略处理。
6. **40004/40011、弱确认、失败、不确定状态均不得自动删除本地原视频**；直接确认成功是否允许删除仍以 APK 用户显式开启且经真机验证的独立设置为准。

### C.4 分页真实行为（重要——APK 必读）

| 参数 | 行为 | 证据等级 |
|---|---|---|
| 默认（无参数） | 返回 ~100 个文件 | API_CHECKED（150 文件目录测试） |
| `page=1` / `page=2` | **返回相同数据——page 参数不可靠** | API_CHECKED |
| `page_size=200` | 返回全部文件（157 个） | API_CHECKED |
| `page_size=1000` | 返回全部文件 | API_CHECKED |
| `page_size` 上限 | **MaxPageSize = 2000**（超出被服务端截断） | SOURCE_CHECKED: provider.go:721 |
| 分页元数据 | 响应中**无** total_count / next_page_token | API_CHECKED |

**⚠️ APK 安全策略**：
- 在当前约定下，弱确认列表请求显式传 `page_size=1000`，避免默认 100 条限制。
- **超过 1000 条就可能截断**；即使服务端配置上限为 2000，也不能把 1000 条结果当作全目录，亦不能把增大 page_size 当作无限规模解决方案。
- 查询结果若达到本次请求条数上限，或者无法证明包含目标文件的完整范围，应保留任务为「确认不充分」，**不删除原件、不自动判定成功，也不以“未找到”为依据盲目自动重传**。
- 隔离测试观察到 `page=1` 与 `page=2` 重复，原因尚未确证；在明确分页协议前不要依赖它完成枚举。

## 四项历史协议问题最终答案

### 1. policy_id

**答案**：可选。缺省时后端自动使用默认存储策略。设备 Token 可调 `GET /file?uri=cloudreve://my/移动端取证` 获取 `storage_policy.id`，也可直接不传。[API_CHECKED: 有/无均 code=0]

### 2. 会话状态查询

**答案**：**不存在**设备 Token 可用的会话详情或已传分片查询端点。APK 无法在进程重启后从服务端查询已传分片，需在本地持久化上传进度。[SOURCE_CHECKED: 路由仅有 PUT/POST，无 GET session]

### 3. 40004 弱确认范围

**答案**：按**完整 URI 精确匹配**。仅同一目录下同文件名触发。不同目录同名不冲突。APK 弱确认必须在预期上传目录内按精确文件名查找。[API_CHECKED + SOURCE_CHECKED: CreateFile → fs.NewUriFromString]

### 4. 分页

**答案**：隔离环境中 `page=1` 和 `page=2` 返回相同数据，暂时**不能依赖该参数可靠遍历**。`page_size` 在测试中有效，默认 100；源码引用的 `MaxPageSize=2000` 是该服务端的配置/限制依据，具体运行配置以现场为准。APK 弱确认请求显式传 `page_size=1000`，但**达到 1000 条即不能证明目录结果完整**。未找到目标文件时应按 §C.3 判断是否为「确认不充分」，保留任务和原件，避免盲目重传。[API_CHECKED: 150 文件隔离测试 + SOURCE_CHECKED: provider.go:721]

## APK 开发方需特别注意的事项

1. **upload_id 算法命名**：当前实现使用 SHA-256 派生确定性 UUID（非标准 RFC 4122 UUIDv5 的 SHA-1）。服务端将 upload_id 视为不透明标识，无跨端重算要求，**不需要修改**。但文档中不应误称"标准 UUIDv5"。
2. **`name` 字段**：APK 发送的额外 `"name"` 字段被 Go JSON 解码器安全忽略（非严格模式）。无害，可保留。
3. **配对码失败的 JSON 业务码是 `404`，不是 `40004`**；上传目标同名冲突使用的是 `40004`。原基础文档中的“40404 仅用于上传同名冲突”属于笔误，已更正。
4. **HTTP/业务码双层判断**：设备 Token 中间件可返回真实 HTTP 401/403；部分 JWT 业务失败为 HTTP 200 + 非零业务码。不能将任何类型的 HTTP 状态写死为“恒定”。
5. **uri 用原始 UTF-8**：`cloudreve://my/移动端取证/filename` 不 percent-encode 文件名中的中文。
